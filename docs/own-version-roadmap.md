# Своя версия игры: решения и дорожная карта

Записано 21.10.2026 по обсуждению с пользователем; план согласован. Порт завершён: поведение совпадает с Disciples 2
(GOG 3.01), доказано харнессами. Дальше пользователь развивает **свою версию** игры. Этот документ — решения, найденные
факты (с путями) и порядок работ с условиями перехода между этапами. Исследование — четыре подагента только чтением
(архитектура и сеть, интерфейс, раскладка репозитория и моддинг, замеры Tidewill), опора — скиллы `game-design-knowledge`,
`gdscript-knowledge`, `csharp-knowledge` (github.com/Betreazen).

## 2. Что устарело в устройстве (факты)

Проверено чтением кода 21.10 (`main` e0438d4a).

- **Нет модели команд и событий.** Godot зовёт ~40 методов сессии напрямую (`Session.MoveStack`, `CastSpell`, `EndTurn`…).
  `ITurnObserver.Battle(BattleState)` возвращает ходы — правила ждут экран; ИИ в рабочем потоке стоит в `AiHooks.Ask`, пока
  главный поток показывает шаг (`godot/scenes/map/MapView.AiTurn.cs`). Итог дня — строки (`DayReport`). Исключение —
  `BattleSession` (`BattleCommand`, «стоп и ждём команду»). Без команд нет реплеев, отмены, сети, ИИ в фоне.
- **`GameSession` — god-класс в проекте данных:** `src/Engine.Play/Play/GameSession*.cs`, 26 файлов, 8 237 строк, ~160
  публичных методов: правила дня, бой, ИИ, внешний вид (`Looks`), читы, экспорт. `LastEdict.Data` ещё и тянет Kaitai/NDbfReader и
  читатель корпуса.
- **Правила — выгрузка DBF:** `data/rules/G*.json` (`{"table","columns"}`), id `g000aa0002`, коды `CLASS 1..25`,
  `SOURCE 0..7`; 50 чтений столбцов по имени в интерфейсе (`r.GetString("NAME_TXT")`). Слоя модов для правил нет —
  `GameBook.Load(RulesDir)` читает только базу.
- **Эффекты атак — закрытый `switch`:** `AttackClass` (23 класса `LattC`, `src/Engine.Rules/Battle/Model.cs`), разбор в
  `Attacks.cs` (42 упоминания), `AiStrength` (19), `AiTargets` (17), `AiRareTargets` (15), `BattleSim` (10), звук
  `BattleSoundPlan.ClassSounds`, текст `UnitCardLogic.ClassTexts`. Новая механика = правка ядра в пяти местах.
- **Ограничения 2001 года в коде:** 6 клеток отряда (`GroupArrange.CellCount`, `UnitGroupLayout.Positions`, литералы
  `[-1,-1,-1,-1,-1,-1]`, `cell % 2`), 7 слотов (`Equipment.SlotCount`), ровно 5 видов маны (поля `Bank`), расы — числа
  (нейтралы `= 4` минимум в 6 местах: `EventConditions.NeutralRace`, `AiTactics.Defend`, `GameSession.Events`…), холст
  800×600 (`ScreenFit`, `BattleScene.CanvasWidth`), карта квадратная (один `MapSize`, 24–144; `new Tile[size, size]` в
  `MapLoader`), сетка влияния ИИ 144×144 (`AiTacticScore.GridSide`). Содержимое в коде: `LeaderCards.Table`,
  `HeroSkills.Descs`, `AudioRegions.Landmarks`.
- **Состояние и вид перемешаны:** сессия держит `MapLooks` (картинки, облики) вокруг `MapState`, всё в сохранении;
  `Tile[,]` и туман `bool[,]` изменяемы; `MapState.With(...)` копирует поля руками и часть не копирует (`Rods`,
  `Subraces`, `Destroyed`).
- **Один генератор на всё:** R250 общий для боя, ИИ, заклинаний (+ CRT `rand`); один лишний бросок сдвигает партию —
  честное A/B баланса невозможно.
- **615 сравнений `OrdinalIgnoreCase`** в правилах и сессии — «мягкие» id и лишнее время (Г12 в `perf-log.md`).
- Самые большие файлы: `GameSession.cs` 1594, `BattleScreen.cs` 1476, `AiTactics.cs` 1278, `MapScreen.cs` 1205; по
  частичным классам MapScreen 4 269 строк, MapView 3 598, BattleScreen 3 528, AiTactics 3 522.

Хорошая основа: правила в .NET без Godot; состояние карты — записи; своё сохранение JSON с версиями; экраны, кадры,
строки, шрифты, сценарии и каталог рас уже слоятся модами (`mods/`, `user://mods`, `mod.json` v1).

## 3. Направления

### 3.1 Фундамент (переделка устройства)

| # | Что | Зачем | Объём / риск |
|---|---|---|---|
| C | **Схема содержимого:** сущности unit, attack, building, spell, item, modifier, race, lord — типизированный JSON, поля по смыслу, enum-строки, id с пространством имён (`base:unit/squire`, `mymod:unit/halberdier`) и `legacyId` для импорта. Базовое содержимое — тоже мод `base`, его выпускает импортёр. C#-record — единственный источник, JSON Schema генерируется (`JsonSchemaExporter`, .NET 9+) → подсказки в редакторе, валидатор, формы Студии. Ванильные данные через новую схему обязаны давать прежние числа харнессов — это и есть проверка каждого шага.

### 3.2 Свои правила (после отделения)

- **Инициатива на раунд вперёд (Р4).** Заранее бросается только случайная часть инициативы раунда N+1 (в начале раунда N);
  модификаторы (ускорение, замедление, гибель, призыв, превращение) применяются вживую — полоса перестраивается от
  эффектов, случайная часть неизменна. «Ждать» действует на текущий раунд. Сейчас: `src/Engine.Rules/Battle/TurnOrder.cs:34`
  (`Build`: инициатива + `rng(BAT_INIT)`, устойчивая сортировка), `BattleSim.BeginRound:427`, `RequeueWaiter:504`,
  `InsertExtraTurns:262`.
- **Раздельные генераторы** (бой, ИИ, добыча, генерация карты) от зерна партии — A/B баланса на одинаковых бросках.
- **5 рас и больше игроков (Р6, Р15):** после E — экраны новой игры и дипломатии под N участников (`MapPalette.RaceSlots = 5`
  уже есть), одинаковые расы у разных игроков, команды с общей победой, расстановка столиц в редакторе, условия победы,
  ИИ против нескольких соперников и в команде; новые расы — сущностью содержимого из мода.
- **Стенд симуляции баланса:** сессия без людей уже играет одним ИИ («Без людей — только ИИ», `GameSession.cs`;
  `BattleSim` считает бои без Godot). Headless-раннер «N партий × зерно» → JSONL (`BattleOutcome`, экономика, длина
  партии) → метрики (`design_metrics.py` скилла game-design): доли побед рас, первый ход, снежный ком.

### 3.3 Интерфейс

- **Полоса очереди ходов.** Сначала (Э1, правил не трогает) — текущий раунд: `BattleSession` (`src/Engine.Play/Battle/BattleSession.cs`,
  поля `_queue`/`_index` закрыты, `:46`) открывает `Upcoming` только для чтения (пометки «пропустит ход», «ждёт») и
  событие изменения очереди. Парализованные и окаменевшие стоят в очереди и пропускают ход (`:546`). Место — полоса фона
  сверху x ≈ 174–627, y 0–85 (~450 px, 9–10 портретов ~44 px), портреты `Faces` 70×85 (233 шт.). Подсветка при наведении,
  связь с юнитом на поле, выключатель в настройках. После Р4 — второй раунд точно.
- **Окно настроек.** Сейчас — `DLG_OPTIONS` оригинала, логика `src/Game.UiModel/Map/MapOptions.cs:155`: 15 флажков, 8 счётчиков
  со ступенями, ползунков нет (`UiKind` без Slider, `src/Game.UiModel/Ui/Screen.cs:10`); `user://settings.json` без версии.
  Не работают `ConfirmEndOfTurn`, `HighAlpha`, `PathBattle`, `InversedPalMap`, `LowEndVideoCard` (только в журнал). Нет окна
  и полного экрана, разрешения, vsync, FPS (ни одного `WindowSetMode`), языка (только `--lang`, `GameData.cs:63,84`),
  переназначения клавиш (VK зашиты в разметку и код), шин звука (громкость на плеер, `GameAudio.cs:101–156`), Theme Godot.
  Сделать: сцена Godot на `Control`, вкладки «Экран», «Звук», «Игра», «Бой», «Управление», «Язык»; одна `Theme` из рамок
  оригинала (9-patch из `DLG_OPTIONS_*`) и EB Garamond; шины Master/Music/Fx/Voice/Ambient; настройки разделами с версией
  схемы и переносом старого файла; плавная скорость боя; «Применить» с откатом режима экрана через 15 с; язык — из
  главного меню с перезагрузкой строк.
- **16:9.** Сейчас вьюпорт 1280×720, все экраны вписываются целиком в внеэкранный `SubViewport` (`ScreenStage.cs`,
  `UiScreenView.Rescale`/`Letterbox` `:527–550`), поля чёрные. Якоря `UiAnchor` есть в данных у всех ~1480 элементов
  (`DlgImport.Anchor`), вид их не читает. Сделать политику вписывания экрана в данных (letterbox / anchors / fill);
  в Last Edict — любое соотношение сторон (Р13).
  Карта: `IMG_MAIN` на всё окно, панели к краю (так делал оригинал на 1024 и 1280). Бой: фоны мест 950×600
  (`BattleScene.cs:48,618`), для 16:9 нужно 1067 — края дорисовать (outpaint) или затемнить. Меню — паспарту
  `BORDER_1024`/`BORDER_1280`. Столица 640×600 — поля или дорисовка.
- **HD-графика.** Сейчас WebP без потерь (728 МБ), `Image.LoadFromFile` → `ImageTexture` (`GfxTextures.cs`, `UiArt.cs`):
  несжатый RGBA8 без mipmap, кэш до 1 ГБ + 256 МБ. Готовый офлайн-апскейл ×2 — `../disciples-modding/hd-mod` (без земли,
  боевых спрайтов и эффектов; сравнение моделей — `model-ratings.md`). Условия: множитель кадра `scale` в описи и аудит
  ~70 мест в 15 файлах, которые считают раскладку по `GetWidth`/`GetSize` (`docs/step6-game-loop.md:196`); логический
  размер — из описи; фильтр `LinearWithMipmaps` для HD-узлов; проверка попадания — по исходнику ×1. Память: ×2 RGBA — ×4
  (для боя неприемлемо), ×2 BC7 + mipmaps — ≈×1,33, ×4 BC7 — только фоны, лица, интерфейс. Сжатие офлайн в DDS
  (`Image.LoadDdsFromBuffer`) или `Image.Compress` в рабочих потоках — замерить. Кэш текстур — LRU по сцене. Порядок
  апскейла: интерфейс, лица, фоны боя, столица, затем спрайты.
  **Процесс апскейла (Р19):** команда выгрузки кладёт выбранную графику PNG в одну папку без подпапок; имена плоские и
  уникальные (путь зашит в имя, например `gfx__BatUnits__<кадр>.png`), рядом опись «плоское имя → исходный путь, размер,
  точка привязки». Пользователь прогоняет папку через Topaz в новую папку с теми же именами. Команда импорта по описи
  раскладывает результат в слой мода графики, пишет `scale`, сверяет пропорции и прозрачность, печатает отчёт (чего не
  хватает, что не того размера) и сжимает текстуры. Дорисованные края фонов боя — тем же импортом, отдельной описью.
- **Геймпад и Steam Deck (Р11, Р12).** Действия — через `InputMap` (сейчас VK зашиты в разметку и код), фокус и навигация
  по всем экранам, курсор карты стиком, подсказки кнопок по устройству ввода, крупный режим интерфейса для 1280×800.
  Переназначение клавиш в окне настроек — сразу для клавиатуры и геймпада. Входит в Э5.
- **Окно построек с зумом и перетаскиванием СКМ.** Сейчас `DLG_BUILD_STRUCTURE`, `src/Game.UiModel/Ui/Windows/BuildLogic.cs`;
  панели веток 437×600; позиции значков — `Rect` из `.dlg`, связь `IMG_%x` ↔ `G000BB0%03x` зашита; **рамки и линии
  нарисованы в фоне** `DLG_*_TYPE_*`; веток ровно пять. Сделать: дерево построек данными слоями модов, автораскладка по
  `LEVEL` и `REQUIRED` (позиция мода главнее); рамки (9-patch) и линии — кодом; область `Control` с `ClipContents` и
  `Node2D` с масштабом и сдвигом: зум колесом к курсору с пределами, тащение СКМ, ограничение по рамке содержимого;
  проверка попадания — в LastEdict.Data с обратным преобразованием (проверки без движка); число веток — из данных.

### 3.4 Инструменты моддинга — «Студия»

План `docs/tools/` (K0–K6, E0–E6) написан 16.10, кода нет: нет `src/LastEdict.Authoring`, CLI `d2mod`, `godot/scenes/studio`,
горячей перезагрузки. Добавить здание сейчас — согласованные правки `Gbuild`, `GbuiList` (по строке на лорда),
`Gunits.UPGRADE_B`/`ENROLL_B`, `data/ui/capital.json`, `IconBld`.

Решение: одно Godot-приложение «Студия» на общем ядре `Authoring` + CLI `d2mod` на нём же. Рабочие пространства:
Карта, Содержимое, Дерево построек, Баланс/Арена, Строки, Экраны. Порядок (Р20): Дерево построек → Содержимое (с
Балансом/Ареной) → Карта. Новые механики модов — данные и C#-плагины доверенных модов (Р21); раз репозиторий публичный
(Р23), Студия и игра явно помечают мод с плагином как «исполняет код». Отмена — командами ядра (A). Игра — отдельный процесс
`--mods --scenario --watch`; горячая перезагрузка — `FileSystemWatcher` и ревизия реестра: экраны, графика, строки,
звук — на лету, правила и карта — перезапуском боя или дня со снимка.

Из старой утилиты (`../disciples-mod/tools/d2mod`, Python) переносить: «папка = сущность» с `icon.png`, артом и
текстами; `graphics_from` (арт готового юнита); автоматические id строк; двухпанельный UX дерева построек
(`ui/buildtree.py`: граф цепочек `REQUIRED` с юнитом здания слева, живая страница меню справа, перетаскивание, проверка
циклов, панель ошибок); цикл баланса «изменил → прогнал → сравнил» (`studio/`), в порте — на `BattleSim` без запуска игры.

**Условие:** схема содержимого (C) и реестр эффектов (D) принимаются до первой строки кода Студии.

Редактор карт без ограничения площади (Р6, Р16): карты квадратные, без потолка размера; все массивы по размеру карты
(тайлы, туман на игрока, A*, сетка ИИ), земля уже рисуется кусками, мини-карта масштабируется. Потолка в редакторе нет; замеры на 256², 512², 1024²
(память тумана, A*, ход ИИ) — при росте стоимости разбить карту на зоны.

### 3.5 Сеть с друзьями (Р5)

Схема «хост-сервер»: игра хоста считает правила (тот же .NET, правила не зависят от Godot) и раздаёт каждому только
видимое (проекция `PlayerView` по туману); маленький посредник на .NET на дешёвом VPS (Р22, WebSocket) выдаёт код
комнаты и пропускает трафик (без открытия портов). Режимы: ИИ на свободных местах, асинхронная партия (состояние и
очередь ходов хранит посредник), таймер хода по желанию хоста; ходы по очереди. Хост в теории видит всё — между друзьями допустимо. Протокол — из `docs/rust-web/03-contracts-and-multiplayer.md`
почти целиком: `command_id`, `expected_view_seq`, `turn_token`, `ViewDelta` с epoch и resync, один обработчик на комнату,
фильтр секретов, `ruleset_id`/`ruleset_hash`. Пошаговость даёт и асинхронный режим (сходил — закрыл игру — друг ходит позже).
Условие — A (команды, события, запросы решения, хеш состояния). «Горячего стула» нет (Р33): люди одной партии — только по сети.

### 3.6 Оптимизация игры

Кадр уже лёгкий: бой 0,32–0,44 мс, расчёт хода ИИ без экрана 18–120 мс на игрока; медленные ходы у пользователя —
ожидание показа (`perf-log.md`, Г20). Остаток по профилю:
1. Копия состояния на каждую команду (`Map.Stacks.ToDictionary`, копия `Plan` по клеткам, `GameSession.cs` ~284–314;
   ~220 мест `ToDictionary`/`new Dictionary`) → паузы GC 120–294 мс за ход ИИ на экране. Лечится с A: рабочая копия внутри
   команды и снимок по требованию, числовые хэндлы вместо строк.
2. `MapView.Reload` строит `MapScene` заново на каждую заявку ИИ (23,6 % `_Process`) → обновление по событиям-дельтам (A).
3. `GD.Print` (13,6 % профиля показа) — за флаг (Э1).
4. LINQ в правилах и сессии (919 вызовов) — чистить по профилю, с `AiTactics`; справочники — `FrozenDictionary`.
5. Кэш текстур — LRU по сцене (обязательно для HD).

Каждая правка — `tools/bench/ab.py` (ABBA, порог 5 %), запись в `perf-log.md`.

### 3.8 Rust — не переходить (Р7)

- Соседний проект пользователя на Rust (замеры на EliteBook):
  партия ИИ против ИИ 94,3 → 15,0 мс, но весь выигрыш — алгоритмы внутри Rust (FxHash вместо FNV −54 %, пул позиций −21 %,
  компактный ключ −28 %, Zobrist −8 %). Вывод проекта: «наш Rust в кадре не виден, время — движок и драйвер». Крупнейший
  выигрыш клиента (загрузка боя −44 %) — уход от 49 152 вызовов `set_pixel` через FFI. Сравнения Rust с C# нет.
- Порт: рендер и загрузку делает Godot на C++ (выигрыша нет); правила и ИИ — оценка ×1–2, а ход ИИ ~100 мс при показе
  1–9 с. Цена — ~90 тыс. строк и 2590 тестов, совместимость доказывать заново.
- Rust оправдан только для браузера (C# в Godot 4.7 в веб не экспортируется) или одного ядра браузер+сервер —
  `docs/rust-web`, отдельный проект.
