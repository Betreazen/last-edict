**Жёсткие рамки**
- Правила не меняются: снимки (`tests/snapshots`) — те же строки. Студия правит **моды**, не базу.
- Ни байта данных оригинала в репозитории и истории (Р3): примеры модов и тесты — на своём `content/test-pack` и своей графике (CC0,
  нарисованной или сгенерированной); картинки, которые пользователь выбирает в Студии, ложатся в **его мод**, не в репозиторий. Снимки экрана
  с графикой игры — только файлами выпуска GitHub `media` (`docs/media.md`), выкладывать — с подтверждения пользователя.
- Студия пишет только в каталог мода (`ModProject`); любая правка — командой с отменой; мод проверяется `ModCheck` до записи.
- Порог полного прогона тестов ≤ 60 с (Р8, Р27). Публикация (пуш, релизы) — только с подтверждения пользователя.
- Графика импорта в корне репозитория не лежит: сцены — с `D2_ASSETS_DIR` (`../disciples-godot/assets`), без ссылок и junction; рабочие
  копии git сносить только `python tools/wt_remove.py <путь> --branch`.
- Ветки `studio-<тема>` → слияние в `main` (`--no-ff`); ревью подагентом и документы — раз на 3–4 правки, замер — на каждую (`bench`,
  `ab.py`, `perf-log.md`). Пользователю — по-русски, коротко. Маршруты по интерфейсу и что удобно — спрашивать у пользователя (он знает
  игру и сам тестирует Студию). Окно ставить на основной монитор `--position 3900,541` (слева телевизор). Тестовые моды пользователя —
  вне репозитория (`../le-mods/<мод>`: `mods/` в git не игнорируется).

**Параллельная работа с Э7**
- **Рабочие копии.** Э7 — в `../last-edict` (ветки `e7-*`). Ты — в своём worktree: `git -C ../last-edict worktree add ../le-studio -b
  studio-<тема> main`. `main` выписан **только** в `../le-wt-main` (`git -C ../last-edict worktree add ../le-wt-main main`, если его нет; если
  `main` выписан в `../last-edict` — договориться с соседом, кто его освобождает). Слияние — `git -C ../le-wt-main merge --no-ff <ветка>`,
  перед этим — `git -C ../le-wt-main log -1` и сообщение соседу «сливаю <ветка>»; после слияния — `git merge main` в свою ветку.
- **Данные импорта** — одни на двоих, только читать: `D2_DATA_DIR=../last-edict` (там `data/`), `D2_ASSETS_DIR=../disciples-godot/assets`.
  Перегенерацию базы (`dotnet run --project tools/RulesImport` в `../last-edict`) и правки схемы, после которых она нужна, — **предупредить
  соседа заранее**; поля схемы добавлять необязательными, чтобы старая база читалась.
- **Связь** — `ListAgents` → `SendMessage` сессии Э7 (её рабочий каталог — `../last-edict`). В начале — одно сообщение: кто ты, ветка,
  worktree. Дальше — коротко и по делу: слияние в `main`, правка общих файлов, перегенерация базы, тяжёлый прогон.
- **Чьё что.** Твоё: `src/Authoring`, `godot/scenes/studio`, `tools/d2mod`, `tools/MapScale`, `docs/tools/*`. Э7: `src/Net*`/`tools/Relay`,

- **Договор о `ruleset_hash`.** Хеш правил партии считает Э7 — от содержимого с модами. Новый вид файлов мода (графика юнита, значки,

**Задачи по порядку** (порядок внутри — уточнить у пользователя в начале: что ему нужнее)
0. **Перед началом:** worktree и `../le-wt-main`, сообщение соседу; `dotnet build`, `dotnet test`, ui-render-check «Студия» зелёные с
   `D2_DATA_DIR`; тестовый мод пользователя — `../le-mods/studio-test`.
1. **Новая постройка из окна** («Дерево построек»): кнопка и форма — имя, требуемая, уровень, цена, ветка, картинка (выбор PNG →
   `icon.png` папки сущности, превью); постройка сама попадает в список построек лорда; удалить и переименовать свою; всё — одной
   командой с отменой; игра с `--watch` показывает её сразу.
2. **Новый юнит** («Содержимое» или своя вкладка «Юниты»): «на основе существующего» — копия с правкой характеристик, атаки, повышения,
   постройки найма; **своя графика юнита в моде**: портрет и лицо (карточка, окна) — PNG в папке сущности по образцу `icon.png`; анимации
   боя — пока ссылкой на анимацию юнита базы (поле схемы), свои кадры — описать формат и сделать, если успеваешь. Игра и окна берут
   графику мода (`GameContent`, `GfxTextures`), HD — как у остальной графики.
3. **Формы вместо таблицы** для частых видов (постройка, юнит, лорд, предмет): поля сгруппированы, ссылки — выбором с поиском и значком,
   ошибки `ModCheck` — у поля; «Содержимое» остаётся для остального.
4. **Объекты на карте** (вехи E2–E3 `docs/tools/map-editor/plan.md`): палитра (столица, город, руина, лавки, ресурсы, мешок, ориентир),
   свойства объекта, отряды (лидер, юниты, предметы, приказ), игроки и расы на карте; «Играть на карте» — партия с объектами.
5. **Мод целиком:** окно конфликтов слоёв (два мода правят одно поле — кто главнее), `d2mod pack` (архив мода с манифестом; хеш — по
   договору с Э7), значки модов не только построек.
6. **Удобство с пользователем:** после каждой задачи — он пробует, правки по его замечаниям; шаги ui-render-check на новые окна, тесты
   ядра на каждую команду (отмена 200 случайных команд — как в Э6).

**Готово, когда:** пользователь в одной Студии, без файлов руками, создаёт постройку со своей картинкой и юнита на основе существующего со
своим портретом, ставит их в дерево и найм, рисует карту с городами и отрядами и играет на ней с горячей перезагрузкой; мод проходит
`ModCheck` и собирается `d2mod pack`; снимки правил — те же; тесты ≤ 60 с; `docs/tools/studio.md` и roadmap §4 — с числами; строка в начале
`docs/HANDOFF.md`; README — строка «Progress» и снимки (с подтверждения пользователя); следующая сессия по Студии — напиши
`docs/session-studio-3-prompt.md`, если работа осталась.
