`docs/own-version-roadmap.md`, решения Р1–Р32, этапы Э1–Э7). Эталон порта `../disciples-godot` (тег `vanilla-reference`) — только для сверок

**Прочитай по порядку:** `CLAUDE.md` → `docs/own-version-roadmap.md` (целиком; для Э5 главное — §1 Р10–Р14, Р19, Р32; §3.3; §4; §5) →
`docs/HANDOFF.md` (первая строка и «Открыто») → `docs/own-rules.md` (что поменял Э4: ключи — id содержимого, полоса на два раунда, команды)

**Что оставил Э4.** Правила, сохранения и сценарии — на id содержимого (`base:unit/knight`); графика и звук импорта называются по id
оригинала — вид берёт имя через `LastEdict.Data.Ui.ArtNames.Of(ключ)`. Потоки генераторов по системам, инициатива на раунд вперёд,
`BattleSession.TwoRounds` — полоса на два раунда (`BattleQueueStrip`: черта раунда, следующий темнее). Одинаковые расы, команды
(`MapPlayer.Team`, `Teams`), больше пяти игроков (test-pack `six-crowns`: 6 игроков, 3 команды), поле дипломатии листает соперников
страницами по три (кнопки — временные стрелки). Стенд баланса `tools/BalanceStand`. Тесты: с импортом 1334 за ~15 с, без данных игры —
CI на `content/test-pack`. Снимки «порт против порта» — арбитр правил: Э5 их **не меняет** (правка вида правил не трогает).

**Жёсткие рамки этапа**
- Правила не меняются: снимки (`tests/snapshots`) — те же строки после каждой правки; изменился снимок — это ошибка, а не правка.
- Ни байта данных оригинала в репозитории и истории (Р3): снимки экрана с графикой игры — только файлами выпуска GitHub `media`
  (`docs/media.md`), и выкладывать их — с подтверждения пользователя.
- Порог полного прогона тестов ≤ 60 с (Р8, Р27). Публикация (пуш, релизы) — только с подтверждения пользователя.
- Графика импорта в корне репозитория не лежит: сцены — с `D2_ASSETS_DIR` (например, `../disciples-godot/assets`), без ссылок и junction.
- Ветки → слияние в `main` (`--no-ff`); ревью подагентом и документы — раз на 3–4 правки, замер — на каждую (кадр, загрузка, память —
  `bench` и `perf-log.md`). Пользователю — по-русски, коротко. Маршруты по интерфейсу спрашивать у пользователя — он знает игру.

**Задачи по порядку (roadmap §4, Э5)**
0. **Проверки экранов без корпуса.** ui-render-check в Last Edict почти целиком шёл на сохранениях и журналах корпуса (`corpus/sample`) —
   свой набор шагов на `content/test-pack` и импортированных сценариях (бой полосы очереди уже проверяется вручную:
   `godot.cmd --headless --path godot res://scenes/battle/BattleScreen.tscn -- --no-mods --check --scenario Mercantile --stacks
   S135KC0000,S135KC0020 --queue-strip --queue-check`); бенч на своих картах. Без этого шага задачи ниже проверять нечем.
1. **Политика вписывания экрана в данных** (letterbox / anchors / fill) и любое соотношение сторон (Р13): 16:9 основное, 16:10 (Deck),
   21:9, 4:3. Якоря `UiAnchor` уже есть у элементов разметки — вид их не читает. Карта — `IMG_MAIN` на всё окно, панели к краю; бой — фоны
   950×600 (края — дорисовка или затемнение); меню — паспарту.
2. **Новое окно настроек** (§3.3): сцена на `Control`, вкладки «Экран», «Звук», «Игра», «Бой», «Управление», «Язык»; одна `Theme` из
   рамок оригинала (9-patch) и EB Garamond; «Применить» с откатом режима через 15 с; язык из меню с перезагрузкой строк; переназначение
   клавиш — сразу для клавиатуры и геймпада (`InputMap`).
3. **Геймпад и Steam Deck** (Р11, Р12): действия через `InputMap`, фокус и навигация по всем экранам, курсор карты стиком, подсказки
   кнопок по устройству, крупный режим для 1280×800. Игра проходится геймпадом.
4. **Экраны под N участников и расы модов** (перешло из Э4): лобби «горячего стула» (сейчас 4 ячейки по расам сценария,
   `HotseatLobbyLogic`), выбор расы (кольцо пяти рас по роду, `ChooseRaceLogic`), каталог рас меню из содержимого (`RaceDef`), а не из
   `data/game/races.json`; места лобби — по игрокам (`HotseatSeat.PlayerId`, `Team`); свой вид кнопок листания дипломатии.
5. **HD-графика** (§3.3, Р19): множитель кадра `scale` в описи и аудит ~70 мест раскладки по `GetWidth`/`GetSize`; выгрузка выбранной
   графики в одну папку для Topaz и обратный импорт по описи; сжатие (BC7/DDS или `Image.Compress`), кэш текстур — LRU по сцене.
