# Схема содержимого правил

Этап Э2, задача C (`docs/own-version-roadmap.md` §3.1). Правила игры читают не таблицы оригинала (`Gunits.dbf`, их выгрузку
`data/rules/*.json`), а **содержимое** — типизированные сущности с именами по смыслу, строковыми значениями перечней и id с
пространством имён мода. Базовое содержимое — мод `base`, его выпускает импорт таблиц оригинала; моды кладут свои слои поверх.

## 1. Сущности

Запись C# — единственный источник формата (`src/Engine.Content/Schema/*.cs`): из неё же выводятся JSON Schema
(`data/content/schema/*.schema.json`, `ContentFiles.Schema` через `JsonSchemaExporter`, описания полей — атрибуты `[Description]`) и
импорт таблиц оригинала (атрибуты `[Legacy("СТОЛБЕЦ")]`, `[Ref("вид")]`, `[LegacyGroup]`).

| Вид (`id`) | Файл | Запись | Из таблиц оригинала |
| --- | --- | --- | --- |
| `unit` | `units.json` | `UnitDef` | `Gunits` + `Gimmu`, `GimmuC` (иммунитеты), `GLabi` (врождённые способности), `GMabi` (земли без штрафа) |
| `growth` | `growth.json` | `GrowthDef` | `GDynUpgr` — шаги роста за уровень |
| `attack` | `attacks.json` | `AttackDef` | `Gattacks` + `Gtransf` (кого призывает или в кого превращает) |
| `modifier` | `modifiers.json` | `ModifierDef` | `Gmodif` + `GmodifL` (элементы) |
| `spell` | `spells.json` | `SpellDef` | `Gspells` |
| `item` | `items.json` | `ItemDef` | `GItem` |
| `building` | `buildings.json` | `BuildingDef` | `Gbuild` |
| `race` | `races.json` | `RaceDef` | `Grace` + `Tleader` (имена героев), `TAiMsg` (сообщения ИИ) |
| `city` | `cities.json` | `CityLevelDef` | `GcityInf` |
| `lord` | `lords.json` | `LordDef` | `Glord` + `GbuiList` (постройки), `GspellR` (исследования) |
| `leader-skill` | `leader-skills.json` | `LeaderSkillDef` | `GleaUpg` — отдельный список: порядок таблицы — порядок равенства выбора ИИ |
| `landmark` | `landmarks.json` | `LandmarkDef` | `GLmark` |
| `thief-action` | `thief-actions.json` | `ThiefActionDef` | `Gaction` |
| `ai` | `ai.json` | `AiAttitudeDef` | `GAI` — строка на отношение ИИ, поля группами (бюджет, лидеры, веса тактики, читы, заклинания) |
| `globals` | `globals.json` | `GlobalsDef` | `GVars` — одна запись `base:globals`, поля группами (бой, вор, земля, дипломатия, сложность, ИИ…) |

Таблицы-перечни `L*.dbf` (`LattC`, `LattS`, `LunitC`…) — перечни C# (`Schema/Enums.cs` и общие с правилами `AttackClass`, `ItemCategory`,
`SpellCategory`, `ModifierElementType`, `ImmunityLevel`, `LordCategory`); в JSON — строкой camelCase (`"class": "boostDamage"`).
Строгость — как у прежних загрузчиков правил: значение вне перечня отвергают только уровень иммунитета (`LImmune`), тип элемента
модификатора (`LmodifE`), категории предмета (`LmagItm`) и заклинания (`Lspell`) — ошибка называет таблицу, строку и столбец. Прочие
числа прежний код брал без проверки, и мод оригинала с незнакомым значением грузился — импорт сохраняет число как есть, в JSON оно
пишется числом. Класс атаки вне `LattC` — ссылка `legacy:class/N`: правила грузятся, удар такой атакой отказывает (`UnknownEffect`), как
прежде. У необязательного перечня ноль вне перечня — «не задано» (моды оригинала пишут 0 в незаполненный столбец). Отсутствующий
столбец — ошибка (прежний `GetInt` падал так же), кроме помеченных `[Legacy(..., Optional = true)]` (`GmodifL.IMMUNITYC/IMMUNECATC`).
Повтор id в таблице — ошибка во всех таблицах (прежде часть таблиц молча брала последнюю строку).

Покрытие проверяет `ContentSchemaTests.Schema_CoversEveryColumnOfEveryTable`: каждый столбец каждой из 25 таблиц прочитан атрибутом или
подчинённым списком. Отброшены только **висячие строки** подчинённых таблиц, у которых нет хозяина (7 строк `GmodifL`, 3 — `Gimmu`/`GimmuC`/
`GLabi` на юнитов, которых нет в `Gunits`): правила их и так не читали, а факт о таблицах держит `F6DataTests` по самим таблицам.

## 2. Id

`<мод>:<вид>/<имя>`: `base:unit/knight`, `mymod:unit/halberdier`. Имена сущностей оригинала — таблица
`src/Engine.Content/Legacy/legacy-ids.json` (ресурс сборки), её выпускает `tools/content_ids.py` из английских имён: имя в нижнем
регистре через дефис, совпавшие — уточнение (юниты — расой, ориентиры — размером), затем номер. Атака названа по первому владельцу
(`base:attack/knight`, вторая атака — `…-2nd`), рост — `…-early`/`…-late`, модификатор — по первому пользователю. Таблица лежит в
репозитории, а не выводится при импорте: в русской копии игры нет английских имён, а id обязаны быть одинаковыми у всех — на них
ссылаются моды. Прежние id таблица не меняет, новые дописывает.

У сущностей оригинала есть `legacyId` (`g000uu0002`): по нему их находят сохранения, карты `.sg` и журналы. **Ключ правил пока —
`legacyId`** (`ContentDef.Key`): модели правил (`UnitType`, `AttackType`…), сохранения и харнессы живут на id оригинала, и переводить
их на новые id — отдельная работа (константы в данные, этап E). У новой сущности мода `legacyId` нет — её ключ правил её id.

Ссылки в содержимом — id сущностей. Ссылка на объект оригинала, которого в содержимом нет (подрасы нейтралов `g000rr0006…0012` у
уровней городов), — `legacy:<id>`. Пустая ссылка оригинала (`g000000000`, пусто) — отсутствие поля.

## 3. Мод и слои

```
data/content/base/      мод base: mod.json + файл на вид (выпускает импорт: GameImporter шаг rules, tools/RulesImport)
data/content/schema/    схемы JSON (для подсказок редактора: "$schema" в каждом файле)
mods/<мод>/content/     слой мода: те же файлы видов, только нужные сущности
```

Файл вида — объект с массивом под именем файла: `{"$schema": "../schema/units.schema.json", "units": [ … ]}`. Слои накладывает
`ContentLayers.Load(база, моды)`:

- нового id ещё нет — сущность добавляется в конец своего вида (полная, проверяется схемой);
- id уже есть — правка по полям: объекты сливаются вглубь, списки и значения заменяются целиком, `null` убирает поле (JSON Merge Patch,
  RFC 7396);
- `"$remove": true` — сущность убирается (только `true`/`false`; убранная и добавленная заново встаёт в конец вида);
- новая сущность мода — только в его пространстве имён (`mymod:…`): правка чужой сущности, которой нет (опечатка, её убрал другой мод),
  — ошибка, а не пустышка; `legacyId` правкой не меняется.

После наложения `ContentChecks` проверяет набор целиком: ключ правил уникален внутри вида без учёта регистра, каждая ссылка ведёт к
сущности нужного вида (или `legacy:…`), одно отношение ИИ на отношение, списки глобальных величин — той длины, которую ждут правила.
Сообщение называет сущность, поле и мод с файлом (у висячей ссылки — и мод, который убрал цель).

Порядок модов — по `dependencies` (обязательны, иначе ошибка) и `loadAfter` (если есть) из `mod.json`, при равенстве — как перечислены;
цикл — ошибка с участниками. Отчёт наложения (`LayerChange`): кто добавил, поправил (какие поля) или убрал сущность и чей слой правил её
перед ним. Игра печатает его строкой `rules: …` при первом чтении правил (`GameData.Rules`).

Пример слоя мода (`mods/strong-knights/content/units.json`):

```json
{
 "units": [
  { "id": "base:unit/knight", "hitPoints": 180, "growth": { "switchLevel": 8 } },
  { "id": "strong-knights:unit/halberdier", "role": "soldier", "level": 1, "race": "base:race/empire", "hitPoints": 120,
    "attack": "base:attack/knight", "hireCost": { "gold": 80 } }
 ]
}
```

Цена — словарь «валюта → количество» (`{"gold": 50, "life": 25}`), валюты — строковые id (`Prices.Currencies`: `gold`, `infernal`,
`life`, `death`, `runic`, `grove`); правила пока считают в `Bank` с шестью полями (этап E — словарь).

## 4. Как правила получают содержимое

`ContentSource.Open(каталог)` — содержимое по каталогу, с кэшем на процесс: каталог базы (`units.json`) читается слоем без модов, каталог
таблиц оригинала (`Globals` копии игры с `.dbf`, выгрузка `data/rules`) импортируется в памяти (`LegacyContent.Import`). Загрузчики
правил (`RulesLoader`, `ModifierLoader`, `EconomyLoader`, `SpellLoader`, `ItemLoader`, `EquipLoader`, `GameBook`) и тексты окон
(`RulesTexts`, `StackTexts`, `RaceNames`, `BuildLogic.LoadTexts`…) берут `ContentSet`; прежние перегрузки с каталогом идут через
`ContentSource.Open`. Поэтому харнессы, которые берут правила прямо из копии игры, проходят ту же схему, что игра, — и прежние числа
харнессов доказывают, что схема ничего не потеряла. Игра (`GameData`) берёт базу `data/content/base` и включённые моды поверх
(`GameData.Rules`); в старом импорте без базы — таблицы `data/rules`.

## 5. Проверки

- `ContentRulesParityTests` — «старая модель = новая»: модели прежних загрузчиков прямо из строк таблиц (`tests/unit/Engine.Play.Tests/LegacyLoaders`,
  их код до схемы) и модели из содержимого совпадают целиком (JSON моделей; ключи по порядку, строки без учёта регистра, `g000000000`
  как пусто) — 18 моделей и все поля `GameBook`, на `data/rules` и на `.dbf` копии игры. Мутация (поменять урон и лечение атаки) ловится.
- `ContentSchemaTests` — каждая строка таблицы — одна сущность, покрытие столбцов, запись мода читается в то же содержимое, слои (правка
  вглубь, добавление, удаление, порядок по зависимостям, отчёт), схемы с описаниями, неизвестное поле — ошибка.
- Все харнессы `Corpus`/`Synth` — прежние числа (`tools/trx_diff.py`: выводы 2638 из 2638 тестов совпали строка в строку).

## 6. Эффекты атак (задача D)

Что делает удар — **эффект** (`src/Engine.Rules/Battle/Effects`), а не `switch` по `AttackClass` в пяти системах. `AttackEffect` — запись:
поведение (`Behavior`: `damage`, `boostDamage`… — код в реестре `AttackEffects`), признаки движка (слоты `CBatAttack*`: `HasPower`,
`ChecksImmunity`, `TargetsAllies`, `RejectsRetreating`, `HasDamage`, `IsDamaging`, `IsDirectDamage`, `IsDot`, `IsOffence`), тело удара
(`Hit`), проверка наложения (`CanPerform`), цель ИИ (`FindTarget`), множители силы ИИ (`AiClassFactor`, `AiDamageFactor`) и данные —
числа ИИ (`EffectTuning`: множители класса и второй атаки, полная точность, «до конца боя», множитель опыта цели) и облик
(`EffectLooks`: имя класса, подпись действия, звук второй атаки, звук тика). Двадцать три класса `LattC` — встроенные эффекты
(`VanillaEffects.cs`) с числами движка; `Attacks.Apply`/`CanPerform`, `AiTargets.FindAttackTarget`, `AiStrength`, звук боя и карточка
юнита спрашивают эффект атаки (`AttackType.Effect`). Порядок бросков генератора задаёт `Attacks.Apply` — эффект его не меняет: выводы
всех 2650 тестов (С1, С2, харнессы боя и ИИ) после переноса совпали строка в строку. Признаки и числа сторожит `AttackEffectsTests`
(списки движка дословно).

В содержимом — вид `effect` (`effects.json`): `{"id": "base:effect/damage", "behavior": "damage", "ai": {…}, "looks": {…}}`; атака
ссылается на эффект (`"effect": "base:effect/heal"`), класс атаки для журналов и сохранений — класс поведения. Мод заводит свой эффект
на встроенном поведении со своими данными (`"behavior": "poison"`, свой звук и числа ИИ) или на своём поведении — реализация
`AttackEffect` в моде с кодом, `AttackEffects.Register`. Поведения нет в реестре — ошибка загрузки с именем эффекта.

## 7. Признаки расы (задача E)

Род расы оригинала (`kind`, `Grace.RACE_TYPE`) правила больше не разбирают числом: у расы в содержимом — `land` (своя земля: её красят
захваты и жезлы, на ней лечатся отряды), `turnOrder` (место в очереди хода), `eventFlag` (номер флага расы в событиях сценария, −1 —
флага нет) и `neutral` (хозяин ничьих отрядов и объектов). Импорт выписывает их явно из рода (`LegacyRaces` в `D2.Rules` — единственное
место, где род — число 0…5); признак, которого нет у расы мода (или снятый патчем `null`), берётся по её роду. Правила читают
`RaceInfo.Terrain/TurnOrder/EventFlag/Neutral`; нейтралы — по признаку, а не «4». Тест — `ContentSchemaTests.RaceTraits_*`.

Игрок отдельно от расы: ключ дипломатии — **сторона** игрока (`MapPlayer.Party`; нет — род его расы, как у движка, где отношения —
пара родов `CMidDiplomacy`). Отношения, союзы, дань, воры, жезлы, события союза и окна дипломатии берут стороны (`Diplomacy.PartyOf`,
`PlayerParties`, `TerrainOfParty` — своя земля стороны по расе её игрока); у партий оригинала стороны — те же числа. Тест —
`DiplomacyPartyTests`: двое одной расы со своими сторонами меняют отношение только своей пары.

Ещё по роду: коды графики и звука в окнах (`LordFaces`, `MapLooks.RaceCode`, `BattleNoteSounds` — через `LegacyRaces.Code`), меню выбора
расы и эльфийский облик лечения; сторон для новой партии из меню (больше игроков, чем родов) пока никто не назначает — это Э4.

## 8. Валюты (задача E)

Цена в содержимом — словарь «валюта → количество» с любыми id валют. В правилах шесть валют оригинала (`Bank.Builtin`: gold, infernal,
life, death, runic, grove) — поля `Bank` (на них стоят правила, окна, формат сохранений и ~850 мест кода и тестов), валюты мода —
`Bank.Extra` (по порядку id, без нулей, копия при записи) с той же арифметикой: поэлементные `Bank.Map`/`Zip` — обрезка, доли, умножение,
нехватка на литьё, доход ИИ (валюта мода — как мана), `+`, `-`, равенством, проверкой цены (`Bank.Covers`, ею пользуются постройка и
литьё) и записью в сохранение (у казны оригинала поля нет вовсе, печать прежняя). `Prices.ToBank`/`Prices.Of` переводят цену ↔ казну без
потерь. Доход, жилы и окна казны в валюте мода — Э4 (ресурсы своей версии). Тесты — `BankCurrencyTests`, `ContentSchemaTests.Price_*`.
