# Правила работы в Last Edict

Своя версия игры «Disciples: Last Edict» (решения Р1–Р31 — `docs/own-version-roadmap.md`) на Godot 4.7.2, C#/.NET 10 (SDK закреплён
в `global.json`). Начало — импорт эталонного порта `disciples-godot` (тег `vanilla-reference`): его поведение совпадает с Disciples II
(GOG 3.01), это доказано харнессами в эталоне. Точка продолжения — **`docs/HANDOFF.md`**, начинать с неё.

## Главное правило

Устройство — по современным игровым стандартам (`docs/principles.md` §2–4): данные отдельно от кода, слои модов, точки расширения, имена
по смыслу, графика обычными форматами; старые форматы игры (`.dlg`, `.ff`, `.dbf`, `.sg`) только импортируются. Принцип Last Edict
(Р10): каждое изменение делает игру удобнее, отзывчивее или проще в развитии. Арбитр правил — **снимки «порт против порта»**
(`tests/snapshots`): правка правил даёт diff, его принимают осознанно (`D2_SNAPSHOTS_ACCEPT=1`) и объясняют в коммите. Сверка с
оригиналом (корпус журналов зонда, харнессы `Corpus`/`Synth`) — только в эталоне `../disciples-godot`.

## Данные оригинала — ни байта в репозитории (Р3)

- Репозиторий публичный (Р23). В git нет и не будет данных игры: таблиц, сценариев, строк, разметки экранов, графики, звука, снимков
  экрана с графикой игры, выписок таблиц в тестах. Их выпускает импорт из копии игры пользователя (`py tools/import_game.py`,
  `docs/publishing.md`) в `data/` и `assets/` — пути в `.gitignore`.
- Тесты и CI — на своём `content/test-pack` (CC0, правят генератор `tools/test_pack.py`, не JSON). Тест, которому нужен импорт, без него
  пропускается с причиной (`tests/Shared/ImportedData.cs`), а не падает.
- Перед каждым открытым коммитом с новыми файлами данных — проверка: нет ли в нём производных файлов игры.

## Безопасность данных

- Рабочие копии git сносить только `python tools/wt_remove.py <путь> --branch`; никаких symlink/junction. Данные — переменными окружения:
  `D2_DATA_DIR` (корень импорта: `data/`, `assets/`), `D2_ASSETS_DIR`, `D2_GAME_DIR` (копия игры для импорта).
- Публикация (пуш в публичный репозиторий, релизы) — только после подтверждения пользователя.

## Как проверять

- `dotnet build LastEdict.sln` и `dotnet test LastEdict.sln` — без данных игры тесты идут на `content/test-pack` (несколько секунд);
  с импортом в корень репозитория — и тесты на данных импорта, и снимки `imported-*`. Порог полного прогона — ≤ 60 с (Р8, Р27).
- Сборка как в CI: `$env:CI='true'; dotnet build LastEdict.sln -c Release` — анализаторы и стиль, предупреждения — ошибки; сейчас 0.
- `python -m pytest -q tests` и `python tools/test_pack.py --check` — инструменты на Python.
- **Снимки** (`tests/Shared/PortSnapshot.cs`): `test-pack-*` — свои карты, 20 дней ИИ и бои; `imported-*` — четыре сценария импорта,
  15 дней и бои (те же строки, что у эталона на `vanilla-reference`). После осознанной правки правил: `D2_SNAPSHOTS_ACCEPT=1 dotnet test
  --filter Category=Snapshot`, посмотреть `git diff tests/snapshots`.
- `dotnet build godot/LastEdict.Godot.csproj` перед запуском сцен; `py tools/ui-render-check.py -j 16` — экраны без окна, числами, ~1,5 мин
  (нужны импорт и `D2_ASSETS_DIR`; партии середины игры — снимки стенда `tools/CheckSaves`, клетки — `tools/ui_check_maps.py`).
- Бенч сцен — `py tools/bench/run_all.py <имя>` → `bench/<имя>.json` (время, память); «до/после» — `py tools/bench/ab.py <до> <после>`,
  запись — `docs/perf-log.md`.
- Всё, что меняет партию, — командой (`docs/game-commands.md`): окна и сцены зовут `Session.Run<T>(команда)`.
- **Сборки:** `Engine.Rules` (правила) ← `Import.Legacy.Formats` (`.sg`/Kaitai, `.dbf`) ← `Engine.Content` (схема содержимого, слои модов)
  ← `Engine.Play` (ядро: партия, команды, бой) ← `Game.UiModel` (окна, меню, графика и звук, диагностика порта) ← `Import.Legacy`
  (импорт копии игры) и `godot/` (игра). Ядро от вида и импорта не зависит.

## Скриншоты прогресса (Р32)

Пока идёт работа над своей версией, **периодически снимать игру и обновлять README**: после каждого заметного изменения вида или
поведения и в конце этапа — новые снимки, пара «Disciples II / Last Edict» для отличий, строка в разделе «Progress», статусы в таблице
отличий. Снимки — файлы выпуска GitHub `media`, **не в git** (на них графика оригинала). Порядок — `docs/media.md`.

## Порядок работы (Р26)

Ветки `<тема>` → слияние в `main` (`--no-ff`), документы и коммиты по-русски, ревью подагентом раз на 3–4 правки, замер — на каждую.

## Пользователь

Пишет по-русски, ответы — по-русски, коротко и по делу. Знает интерфейс игры — маршруты спрашивать у него. Подагентам в задачах повторять
правила безопасности выше.
