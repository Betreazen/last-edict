Своя версия Disciples 2 — **«Disciples: Last Edict»** (Godot 4.7.2 + C#/.NET 10, репозиторий `last-edict`, план —
`docs/own-version-roadmap.md`, решения Р1–Р33, этапы Э1–Э7). Эталон порта `../disciples-godot` (тег `vanilla-reference`) — только для сверок
с оригиналом. Э1–Э6 сделаны (§4 roadmap, «Э6 — ход»). Ты — **этап Э7 «Сеть с друзьями»**: партия людей на разных машинах — хост считает
правила, посредник с кодом комнаты пропускает трафик, ИИ на свободных местах, асинхронный режим и таймер хода. Одновременно другая
сессия делает **«Студию 2»** (создание построек, юнитов и объектов карты в Студии) — с ней общий `main`, общие данные импорта и часть
общих файлов (см. «Параллельная работа»).

**Что оставил Э6.** Окно построек на данных (`BuildTree`, ветки — вид `building-branch`, место мода `tree`), вид с зумом и сдвигом

построек», «Содержимое», «Баланс» (арена на `BattleSim`, стенд партий ИИ), «Карта» (`MapFactory` — карты любой стороны, кисть, отмена по

`tools/bench/run_all.py`, сравнение — только `tools/bench/ab.py` попарно (`map_open` «двугорбый» от сборки мусора — сверять с
`DOTNET_GCgen0size=0x10000000`).

**Что уже есть для сети (Э2–Э5).** Все правки партии — командами (`Session.Run<T>`, `docs/game-commands.md`), журнал команд с хешем

в этом этапе.

**Жёсткие рамки этапа**
- Правила не меняются без осознанного решения: снимки (`tests/snapshots`) — те же строки; сетевая партия обязана давать тот же хеш состояния,
  что та же последовательность команд локально.
- Ни байта данных оригинала в репозитории и истории (Р3): по сети ходят команды и проекции состояния, а не файлы игры; снимки экрана с
  графикой игры — только файлами выпуска GitHub `media` (`docs/media.md`), выкладывать — с подтверждения пользователя.
- Посредник — **маленький**, на .NET, WebSocket (Р22), без правил игры: код комнаты, пересылка, очередь ходов асинхронного режима. Секретов
  (токенов, адресов VPS) в репозитории нет — переменные окружения. Аренда VPS, домен, развёртывание — **вопрос пользователю** (§6), до
  ответа — посредник локально и на второй машине.
- Хост раздаёт каждому только видимое (проекция `PlayerView` по туману); набор модов и их хеш — часть `ruleset_hash`: разные моды — отказ
  входа с понятным текстом; мод, который «исполняет код», в сетевой партии — только если он есть у всех и разрешён.
- Порог полного прогона тестов ≤ 60 с (Р8, Р27). Публикация (пуш, релизы) — только с подтверждения пользователя.
- Графика импорта в корне репозитория не лежит: сцены — с `D2_ASSETS_DIR` (например, `../disciples-godot/assets`), без ссылок и junction.
- Ветки → слияние в `main` (`--no-ff`); ревью подагентом и документы — раз на 3–4 правки, замер — на каждую (`bench`, `ab.py`, `perf-log.md`).
  Пользователю — по-русски, коротко. Маршруты по интерфейсу спрашивать у пользователя — он знает игру. Окно ставить на основной монитор
  `--position 3900,541` (слева телевизор).

**Параллельная работа со «Студией 2»**
- **Рабочие копии.** Ты — в `../last-edict`, на ветках `e7-<тема>` (первым делом уйти с `main` на ветку). «Студия 2» — в своём worktree
  `../le-studio` (ветки `studio-*`). `main` выписан **только** в `../le-wt-main` (`git worktree add ../le-wt-main main`, если его нет).
  Слияние — `git -C ../le-wt-main merge --no-ff <ветка>`, перед этим — `git -C ../le-wt-main log -1` и сообщение соседу «сливаю <ветка>»;
  после слияния — `git merge main` в свою ветку. Сносить рабочие копии — только `python tools/wt_remove.py`.
- **Данные импорта** — в `../last-edict/data`, сосед читает их через `D2_DATA_DIR=../last-edict`. Перегенерацию базы (`tools/RulesImport`)
  и правки схемы, после которых она нужна, — **предупредить соседа заранее**; поля схемы добавлять необязательными.
- **Связь** — `ListAgents` → `SendMessage` сессии «Студия 2» (рабочий каталог `../le-studio`). В начале — одно сообщение: кто ты и ветка.
  Дальше — коротко: слияние в `main`, правка общих файлов, перегенерация базы, тяжёлый прогон.
- **Чьё что.** Твоё: `src/Net*`/`tools/Relay`, протокол, `PlayerView`, `ruleset_hash`, лобби «Мультиплеер» (`MainMenuLogic`). «Студии 2»:
  `src/Authoring`, `godot/scenes/studio`, `tools/d2mod`, `docs/tools/*`. **Общее** (малые коммиты, сосед знает заранее): `src/Engine.Content`
  (схема, `ModInfo`, `ContentLayers`, `EntityFolders`, `ModPlugins`), `src/Game.UiModel/Content/GameContent.cs`, `godot/autoload/GameData.cs`,
  `tools/RulesImport`, `tools/ui-render-check.py`, `tools/bench/*`, `docs/content-schema.md`, `docs/HANDOFF.md`, roadmap §4,
  `docs/perf-log.md`, README «Progress».
- **Договор о `ruleset_hash`.** Функцию хеша правил с модами делаешь ты — одну на всех (её же зовёт `d2mod pack` «Студии 2» для манифеста
  мода). «Студия 2» добавляет новые виды файлов мода (графика юнитов, значки): что меняет правила — в хеш, что только графика — нет; сосед
  сообщает о новом виде, ты держишь тест «какие файлы мода входят в хеш».
- **Тяжёлые прогоны** (`ui-render-check -j 16`, бенч, `ab.py`, партия двух машин) — не одновременно с соседом: спросить; «до» мерить в
  `../le-wt-main`. Замер, снятый при чужом прогоне, — переснять.
- **Документы:** в `HANDOFF.md` — своя строка сверху с датой и «Э7», строку «Студии 2» не переписывать; в roadmap §4 и `perf-log.md` — свои
  разделы.

**Задачи по порядку (roadmap §4, Э7)**
0. **Перед началом:** ветка `e7-<тема>`, worktree `../le-wt-main`, сообщение соседу; после пулла — `dotnet run --project tools/RulesImport`
   (база содержимого: ветки окна построек; соседа — предупредить); проверки и бенч зелёные.
1. **Протокол без сети:** сообщения (`command_id`, `expected_view_seq`, `turn_token`, `ViewDelta` с epoch, resync) и проекция `PlayerView` по
   туману — в `src/` без Godot; тест «две проекции по командам хоста = локальная партия», фильтр секретов (чужие отряды под туманом, казна,
   заклинания), `ruleset_hash` от содержимого с модами.
2. **Посредник** (`tools/Relay` или `src/Net.Relay`): комната по коду, пересылка, переподключение, хранение состояния и очереди ходов для
   асинхронного режима; проверки — сценарии клиентов без Godot.
3. **Хост и клиент в игре:** лобби «Мультиплеер» (создать комнату, войти по коду, места: человек, ИИ, свободно; моды и `ruleset_hash`),
   ход по очереди как в оригинале, таймер хода по желанию хоста, бой — у хоста, клиент получает дельты; потеря связи — resync.
4. **Асинхронный режим:** сходил — закрыл игру — друг ходит позже; состояние у посредника; уведомление о своём ходе.
5. **Две машины:** партия ПК + вторая машина (ноутбук `laptop` или EliteBook `elitebook` — Linux, Р11; порядок подключения —
   `~/.claude/docs/*-ssh.md`) через посредника; обрыв и resync; замеры — задержка хода, трафик дня, память.

**Готово, когда:** партия двух машин через посредника по коду комнаты доигрывается до конца дня и боя с тем же хешем, что локальный повтор
журнала; обрыв связи и resync восстанавливают партию; асинхронный ход переживает закрытие игры; снимки правил — те же; roadmap §4 отмечен
с числами; строка в начале `docs/HANDOFF.md`; README — строка «Progress» и снимки (с подтверждения пользователя); следующая сессия —
напиши `docs/session-e8-prompt.md` (план после Э7 — с пользователем).
