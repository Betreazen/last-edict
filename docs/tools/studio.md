# Студия Last Edict и `d2mod`

Э6 (roadmap §3.4, Р20, Р21): одно приложение на Godot на общем ядре `src/Authoring` (`LastEdict.Authoring`) и командная строка
`tools/d2mod` на нём же. Проект Студии — **каталог мода**; пишет Студия только в него (база только читается — правка базы ложится слоем
мода). Устройство и прежний план — `docs/tools/studio-architecture.md`, `docs/tools/modding-kit/*`, `docs/tools/map-editor/*`.

## Запуск

```
godot --path godot res://scenes/studio/Studio.tscn -- --open <каталог мода> [--lord <id>]
dotnet run --project tools/d2mod -- new mods/towers --id towers         # новый мод
```

Мод нужен с `mod.json` (`{"id": "towers", "name": "Towers"}`). Графика и база — как у игры (`D2_ASSETS_DIR`, `data/content/base`).

## Рабочие пространства

| Вкладка | Что делает | Ядро |
| --- | --- | --- |
| **Дерево построек** | слева — граф цепочек требований построек лорда (узел — значок, имя, юнит постройки; стрелку тянут от требуемой к постройке, разрывают — Ctrl/правой); посередине — живая страница окна построек (то же дерево, что в игре: вкладки, зум колесом, тащение средней кнопкой); значок переносится мышью в другую клетку (место мода главнее автораскладки), правая кнопка — вернуть к автораскладке; справа — **форма постройки** (Студия 2): «Новая постройка» — название (имя каталога само, транслитом), описание, картинка (любой PNG/JPG/WebP вписывается в значок 77×74, крупный — HD ×2…×4), требуемая (со значками), уровень, цена, категория, ветка юнитов, вкладка окна, «у всех лордов расы»; выбранная в графе или на странице — те же поля, «Применить» — одной командой, у своей — «Переименовать» и «Удалить» (из списков лордов — вычеркнуть, требовавшие её — на её требуемую); снизу — панель ошибок | `TreeWorkspace` (+ `.Buildings`), `BuildTreePreview` |
| **Юниты** | слева — юниты (раса, поиск; свои — светлее, правленые — золотом), посередине — форма: название, описание, роль, раса, ветка, уровень, жизнь, броня, регенерация, лидерство, опыт, ход, размер; атака — инициатива, точность, урон, лечение (правка атаки базы даёт юниту свою копию, другие юниты базы не меняются); найм — список расы, постройка, цена; повышение — из кого вырастает и чьей постройкой; графика — чьи анимации и значок; справа — лицо 70×85, портрет 130×142 и картина 350×450: своя картинка (файл вписывается в место, HD) или графика основы. «Новый на основе выбранного» — копия со своей атакой и графикой основы | `UnitWorkspace` |
| **Содержимое** | любой вид по схеме: список (свои — светлее, правленые — золотом), поля с описаниями схемы, «база / мод / итог», правка по типу поля (перечень и ссылка — выбором), сброс к базе, новая сущность каталогом (копия выбранной) | `ContentWorkspace` |
| **Баланс** | «Арена» — бои пар отрядов сценария на `BattleSim` без мода и с модом на одних зёрнах; «Стенд» — партии ИИ (`BalanceStand`), доли побед рас «было → стало». Без запуска игры | `BalanceWorkspace` |
| **Карта** | карты мода любой стороны (квадрат, без потолка): новая (`MapFactory`: столицы по кругу, деревни и нейтралы по площади), кисть грунта и земли расы радиусом 0…3, мазок — одна команда отмены, запись в `data/scenarios` мода с карточкой каталога, «Играть на карте» | `MapWorkspace`, `MapFactory` |

Правки — командами ядра (`EditCommands`: поле, новая сущность, удаление, текст, картинка, переименование, пачка) с общей историей: **Ctrl+Z / Ctrl+Y**, запись —
**Ctrl+S**. Мод с C#-плагином (`plugins/*.dll`) помечен в заголовке «⚠ исполняет код».

## Игра рядом: горячая перезагрузка

«Играть» записывает мод и запускает игру **отдельным процессом** (`MapScreen.tscn -- --mods <мод> --watch [--scenario <id>]`): падение
партии не роняет Студию. С `--watch` игра следит за каталогом мода (`ContentWatcher`): записали — она перечитывает реестр (ревизия растёт,
строка `reload revision=N …`), карта перезапускается **со снимка партии** (тот же день и состояние, новые правила, строки, графика) и снова
открывает столицу и окно построек на той же ветке. Изменение `plugins/` — `code=restart-needed`: сборки в процесс второй раз не грузятся.
Студия тоже следит за модом: правку снаружи (`d2mod`, редактор) она перечитывает.

## Папка = сущность

`content/<вид>/<имя>/entity.json` + `strings.<язык>.json` + картинки — `docs/content-schema.md` §10. Id строк автоматические
(`<id>#name`). Картинки (`EntityArt`): постройка — `icon.png` (значок 77×74, архив `IconBld`), юнит — `face.png` (лицо 70×85), `portrait.png`
(портрет 130×142, `Faces`), `picture.png` (картина 350×450, `Events`); файл крупнее места в целое число раз — HD. Картинка лежит в документе
мода: выбор и замена отменяются, на диск идут при записи. У юнита мода графика боя и карты — основы (`baseUnit`), свои лицо, портрет и картина —
главнее неё (только картинки модов: графика оригинала так не подменяется). В `ruleset_hash` (Э7) картинки не входят.

## `d2mod`

```
d2mod new <мод> --id <id> [--name <имя>]
d2mod validate <мод> [--data <data>]            # mod=<id> entities=N errors=E warnings=W executes_code=0|1; код 1 — есть ошибки
d2mod add <мод> <вид> <имя> [--json <тело>] [--file]
d2mod set <мод> <id> <путь> <JSON>               # правка чужой сущности — в слой мода
d2mod unset <мод> <id> <путь>
d2mod text <мод> <id> <язык> <ключ> <текст>
d2mod file <мод> <id> <файл> [<png>]             # картинка сущности-каталога (icon.png, face.png…), без png — убрать
d2mod rename <мод> <id> <новое имя>              # своя сущность-каталог; ссылки мода — следом
d2mod apply <мод> <сценарий.json> [--undo-check] [--dry]
d2mod tree <мод> --lord <id>
d2mod run <мод> [--scenario <id> --player <id>] [--watch]
```

Проверка мода (общая для окна и `d2mod`, `ModCheck`): `MOD001` — слой не накладывается на базу (текст загрузки игры), `MOD010` — требования
построек по кругу, `MOD011` — постройка не у лорда, `MOD012` — две постройки в одной клетке дерева, `MOD090` — исполняет код.

## Проверки без окна

- `dotnet test`: `AuthoringTests` (папка = сущность, отмена 200 случайных команд, правка базы в слой, запись только в мод, проверка,
  плагины, наблюдатель), `BuildTreeTests`, `StudioWorkspaceTests`.
- `Studio.tscn -- --open <мод> --check --script <шаги.json>` — после каждого шага строка `studio: …`, `content: …`, `balance: …`, `map: …`.
- ui-render-check: «перезагрузка мода» (игра с `--watch`, мод правит `d2mod`), «Студия» (шаги дерева, содержимого, арены и карты).
