# Команды партии и журнал команд

Этап Э2 «Фундамент под харнессами», задача A (`docs/own-version-roadmap.md` §4). Цель — ядро-редьюсер
`Apply(state, command) → (state', events)`: всё, что меняет партию, — запись-данные, которую можно записать, переслать по сети и
повторить. Правила игры не меняются: харнессы по корпусу и синтетике дают те же числа после каждого шага.

## 1. Команды и журнал (шаг A1)

- **`GameCommand`** (`src/Engine.Play/Play/Commands/GameCommand.cs`) — 55 записей, по одной на метод `GameSession`, который меняет состояние
  или поток случайных чисел: ход отряда (`planMove`, `revealFrom`, `moveStack`, `actInPlace`, `leftFort`, `leaveFort`), конец хода
  (`endTurn` — ходы ИИ, события, начало дня), город и столица (`build`, `hireUnit`, `hireLeader`, `growCity`), магия (`castSpell`,
  `castItem`, `researchSpell`), отряд и предметы (`dismissUnit`, `swapUnits`, `moveInGroup`, `equipItem`… `giveItems`), лавки и лагеря
  (`buyItem`, `hireMercenary`, `train`…), воры, дипломатия (`giveGold`, `proposeAlliance`, `answerTrade`…), бой (`startBattle`,
  `endBattle`, `commitBattle`, `nextEventBattle`), сообщения, победа и чит опыта. В JSON имя — поле `"$cmd"`.
- **`GameSession.Execute(command)`** → `CommandResult(Value, Report, Events, Answers)`: значение прежнего метода, строки отчёта,
  события хода по порядку, решения снаружи (§2). События — те же вызовы наблюдателя хода (`ITurnObserver`), записанные как данные
  (`PlayerTurnStarted`, `StackMoved`, `SightHappened`, `OfferMade`, `HumanTurnStarted`, `BattleFinished`, `ScenarioEventFired`,
  `BattleShown`); показ получает их как прежде — записчик стоит перед наблюдателем.
- **`StateHash.Of(session)`** — SHA-256 каноничного JSON снимка (`GameSession.Snapshot`: состояние и потоки случайных чисел; время
  сохранения постоянное, ключи по порядку). Один хеш — партии неотличимы для правил.
- **`CommandJournal`** — хеш начала и команды с хешем после каждой и решениями; строки JSON (`ToJsonLines`/`FromJsonLines`);
  `Replay(session)` повторяет на сессии с того же начала (решения — из журнала, наблюдатель сессии на время повтора подменён) и падает
  на первом расхождении с номером команды. `GameSession.Journal` задан — `Execute` пишет каждую команду верхнего уровня.

## 2. Бой по шагам и решения снаружи (шаги A1b, A2)

**Бой человека** (`src/Engine.Play/Battle/BattleInputs.cs`). Экран боя зовёт методы `BattleSession`; сессия пишет каждый внешний вызов
записью `BattleInput` (`"$act"`: `startTurn`, `attack`, `summon`, `defend`, `retreat`, `skip`, `wait`, `aiDecide`, `useItemAt`,
`useItemOn`, `useItem`, `resolve`, `playOut`, `setAuto`; юниты — по id; вложенные вызовы — автобой, ход ИИ — не пишутся, отклонённое
действие пишется). `BattleSession.Played(crtDraws)` → `BattlePlay(Setup, Actions, CrtDraws)`: устройство сессии, действия и сколько
чисел `rand()` процесса экран взял при открытии (вариант фона, `MapScreen.BackgroundDraw` — 2). `BattlePlay.Replay(state, rng, …)`
играет бой заново тем же журналом ходов.

- Бой человека с карты и бой эффекта: `startBattle` → экран играет на генераторе партии → `endBattle(log, play)` → `commitBattle`
  (`MapScreen.cs`, `MapScreen.Overlays.cs`). Экран берёт числа генератора до команды `endBattle`; при повторе журнала
  (`GameSession.Replaying`) команда играет бой сама по `play` и берёт те же числа.

**Решения снаружи команды** — то, что команда получила от наблюдателя, пока шла, данными при записи журнала (`JournalEntry.Answers`,
`"$ans"`), с номером вызова наблюдателя за команду (`Call`):

- **`BattleAnswer`** — запрос решения боя `ITurnObserver.DecideBattle(state)` → `BattleDecision(Log, Play)`. Бой ИИ с отрядом человека
  в ходе ИИ играет экран (`MapView.AiHooks.DecideBattle`, действия — `AiBattle.Played`); по умолчанию `DecideBattle` берёт журнал
  прежнего `Battle` (наблюдатели проверок). Повтор: `ReplayObserver` играет `Play` на генераторе партии; ответ только журналом —
  возвращает журнал (числа, которые брал такой наблюдатель, повтор не возьмёт — хеш это покажет).
- **`NestedCommand`** — команда, поданная, пока команда ждала на вызове наблюдателя: ответ человека на предложение ИИ из окна, пока
  ход ИИ стоит (`OfferLogic`, сделки в `MapScreen.Windows.cs`/`Courier.cs` идут через `Execute`). Пишется к самому внешнему идущему
  вызову; повтор исполняет её после этого вызова.

Тесты (`tests/unit/Engine.Play.Tests/CommandJournalTests.cs`): каждая команда и каждое действие боя переживают JSON (и ни одно не забыто);
партия «Растленная власть» командами повторяется с тем же хешем; партия без человека, где бои ИИ играет «экран» по шагам со своими
случайными решениями и двумя числами фона, а подарок золота подан изнутри хода, повторяется по журналу без наблюдателя с тем же хешем
и индексом генератора; журнал без решений расходится; иное начало или иная команда — ошибка.

**Правила исполнения.** Конец хода в сцене — тоже команда (`MapView.EndTurn`/`RunAi` → `Execute(endTurn)`), иначе ответ человека
стал бы командой верхнего уровня посреди хода ИИ. Команда во время команды допустима только пока внешняя стоит на вызове наблюдателя
(рабочий поток ждёт, главный подаёт ответ); иначе `Execute` отказывает. С журналом каждая команда сверяет хеш перед собой с хешем после
прошлой записи: правка партии мимо `Execute` отмечается в записи (`JournalEntry.Outside`), и повтор отказывает на ней с причиной, а не
расходится молча дальше. Повтор не пишет сам себя (`Journal` сессии на время повтора снят). Бой, отданный одним журналом ходов без
действий, повтор называет в сообщении о расхождении.

Ход ИИ остаётся синхронным кодом на рабочем потоке сцены: «запрос решения» — вызов наблюдателя, который сцена держит, пока человек
не ответит. Остановить ход на запросе и продолжить отдельной командой (ход ИИ как возобновляемый процесс) — дальнейший шаг, не нужный
для журнала: решение и так записано и повторяется.

## 3. Интерфейс через команды и журнал живой партии (шаг A1c)

- **Всё, что меняет партию из интерфейса, — команда.** Окна (`src/Game.UiModel/Ui/Windows`) и сцены карты зовут `Session.Run<T>(команда)`
  (`Execute` с типизированным значением); прямых вызовов методов-правил не осталось (план хода с бросками R250 — `PlayerMove.Plan` через
  `planMove`; лечение и воскрешение в городе — `healUnit`, `reviveUnit`).
- **Аудит:** `GameSession.ChangedOutsideCommands` — партия меняется вне `Execute`. Сцена с `D2_COMMAND_AUDIT=1` печатает место
  (`command-audit Окно.Метод → GameSession.Метод`); ui-render-check ставит переменную всем запускам, собирает места и проваливается, если
  они есть («мимо команд»). С журналом каждая команда сверяет отпечаток партии (ссылка на состояние и места генераторов) с отпечатком
  после прошлой: сдвиг — `JournalEntry.Outside` (кроме чисел, которые до `endBattle` законно брал экран боя).
- **Журнал живой партии:** сцена с `D2_COMMAND_JOURNAL=<файл>` пишет при показе карты сохранение начала (`<файл>.start.d2save`) и при
  выходе — журнал (заголовок — хеш начала и настройка `EventBattlesOnScreen`). `dotnet run --project tools/JournalReplay -- <файл>`
  повторяет партию без сцены и сверяет хеш после каждой команды: так сохранение и журнал игрока становятся баг-репортом.
  Шаг ui-render-check «журнал команд»: «Drega Zul» (конец хода с ходом ИИ, ход в зону события, попап, бой события на экране) и партия из
  меню с ответом на предложение союза в ход ИИ — повтор сходится.
- Найдено этим шагом: итоги хода людей (`GameState.Summaries`, их собирает сцена) в хеш не входят — это данные окон; запись памяти тактики
  ИИ (`AiTacticMemo.Records`) упорядочена по ключу — словарь отдавал записи в порядке хеша строк, свой у каждого процесса, и одна и та же
  партия сохранялась по-разному от запуска к запуску.
