**Жёсткие рамки**
- Правила не меняются: снимки (`tests/snapshots`) — те же строки. Студия правит **моды**, не базу.
- Ни байта данных оригинала в репозитории и истории (Р3): примеры модов и тесты — на своём `content/test-pack` и своей графике (CC0,
  нарисованной или сгенерированной); картинки, которые пользователь выбирает в Студии, ложатся в **его мод**, не в репозиторий. Снимки экрана
  с графикой игры — только файлами выпуска GitHub `media` (`docs/media.md`), выкладывать — с подтверждения пользователя.
- Студия пишет только в каталог мода (`ModProject`); любая правка — командой с отменой; мод проверяется `ModCheck` до записи.
- Порог полного прогона тестов ≤ 60 с (Р8, Р27). Публикация (пуш, релизы) — только с подтверждения пользователя.
- Графика импорта в корне репозитория не лежит: сцены — с `D2_ASSETS_DIR` (`../disciples-godot/assets`), без ссылок и junction; рабочие
  копии git сносить только `python tools/wt_remove.py <путь> --branch`.
- Ветки `studio-<тема>` → слияние в `main` (`--no-ff`); ревью подагентом и документы — раз на 3–4 правки, замер — на каждую (`bench`,
  `ab.py`, `perf-log.md`). Пользователю — по-русски, коротко. Маршруты по интерфейсу и что удобно — спрашивать у пользователя (он знает
  игру и сам тестирует Студию). Окно ставить на основной монитор `--position 3900,541` (слева телевизор). Тестовые моды пользователя —
  вне репозитория (`../le-mods/<мод>`: `mods/` в git не игнорируется).

**Задачи по порядку** (порядок задал пользователь 25.10: сначала постройки, юниты и их механики, потом карта и всё, что с ней связано)
0. **Перед началом:** worktree `../le-studio` и `../le-wt-main` уже созданы (25.10), база содержимого перегенерирована; сообщение соседу;
   `dotnet build`, `dotnet test`, ui-render-check «Студия» зелёные (своя `data/`, `D2_ASSETS_DIR`; проверено 25.10: тесты 757 + 687); тестовый мод пользователя — `../le-mods/studio-test`.
1. **Новая постройка из окна** («Дерево построек»): кнопка и форма — имя, требуемая, уровень, цена, ветка, картинка (выбор PNG →
   `icon.png` папки сущности, превью); постройка сама попадает в список построек лорда; удалить и переименовать свою; всё — одной
   командой с отменой; игра с `--watch` показывает её сразу.
2. **Новый юнит** (своя вкладка «Юниты» или форма в «Содержимом»): «на основе существующего» — копия с правкой характеристик (жизнь,
   броня, инициатива, точность, урон, опыт, повышение, лидерство, размер), постройки найма и ветки повышения; портрет и лицо (карточка,
   окна) — PNG в папке сущности по образцу `icon.png`, игра и окна берут их через `GameContent`/`GfxTextures`, HD — как у остальной
   графики. **Модели и анимации боя пользователь отложил** («будем думать потом»): анимации — ссылкой на анимацию юнита базы (поле схемы);
   инструменты под свои кадры (формат листа, импорт, проверка) — можно сделать, сами модели и анимации — не делать.
3. **Атаки, эффекты, характеристики, ауры.** Новая атака из реестра эффектов (Э2 «D»: урон, яд, ожог, паралич, окаменение, лечение,
   превращение…) с параметрами, источником, дальностью и целями; иммунитеты и защиты; новые характеристики и **ауры** (постоянный эффект
   на свой отряд, соседей, клетки или врага рядом) — сначала данными, если реестр позволяет; если нужен новый вид эффекта — точка
   расширения в ядре (новое только для модов, правила базы и снимки — те же) и форма в Студии; арена «Баланса» сразу показывает, как
   правка меняет бои. Проверки — тесты эффекта на `BattleSim` и шаг ui-render-check боя с атакой мода.
4. **Формы вместо таблицы** для частых видов (постройка, юнит, атака, лорд, предмет): поля сгруппированы, ссылки — выбором с поиском и
   значком, ошибки `ModCheck` — у поля; «Содержимое» остаётся для остального.
5. **Карта и всё с ней связанное** (вехи E2–E5 `docs/tools/map-editor/plan.md`): палитра (столица, город, руина, лавки, ресурсы, мешок,
   ориентир), свойства объекта, отряды (лидер, юниты, предметы, приказ), игроки и расы, события; «Играть на карте» — партия с объектами.
6. **Мод целиком:** окно конфликтов слоёв (два мода правят одно поле — кто главнее), `d2mod pack` (архив мода с манифестом; хеш — по
   договору с Э7), значки модов не только построек.
7. **Удобство с пользователем:** после каждой задачи — он пробует, правки по его замечаниям; шаги ui-render-check на новые окна, тесты
   ядра на каждую команду (отмена 200 случайных команд — как в Э6).

**Готово, когда:** пользователь в одной Студии, без файлов руками, создаёт постройку со своей картинкой и юнита на основе существующего со
своим портретом и своей атакой или аурой, ставит их в дерево и найм, рисует карту с городами и отрядами и играет на ней с горячей перезагрузкой; мод проходит
`ModCheck` и собирается `d2mod pack`; снимки правил — те же; тесты ≤ 60 с; `docs/tools/studio.md` и roadmap §4 — с числами; строка в начале
`docs/HANDOFF.md`; README — строка «Progress» и снимки (с подтверждения пользователя); следующая сессия по Студии — напиши
`docs/session-studio-3-prompt.md`, если работа осталась.
