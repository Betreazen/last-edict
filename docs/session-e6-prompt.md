(`VectorFonts`, `GameData.Fonts`), резкость CAS (`ScreenStage.SetSharpness`), «Размер окон» над картой (`UiScreenView.SlotScale`); карта и

Сложенные картинки (рамка с портретом, раны, значки) собираются в множителе HD (`ImageScales.AtScale`/`Composed`, `GfxTextures.CanvasHd`):
`GfxTextures.Canvas` отдаёт HD уменьшенной до логических точек — для текстур не брать. Проверки (ui-render-check, снимки) идут без модов и
настроек показа: HD-пути смотреть снимками окна (`--scale hd --vector-text --sharpen 40`, `--stage-shot`; окно ставить на основной монитор
`--position 3900,541` — у пользователя слева телевизор, `0,0` открывает игру на нём).

**Жёсткие рамки этапа**
- Правила не меняются без осознанного решения: снимки (`tests/snapshots`) — те же строки; если правка правил нужна (дерево построек данными
  меняет порядок перебора?) — diff снимков принимают осознанно (`D2_SNAPSHOTS_ACCEPT=1`) и объясняют в коммите.
- Ни байта данных оригинала в репозитории и истории (Р3): снимки экрана с графикой игры — только файлами выпуска GitHub `media`
  (`docs/media.md`), и выкладывать их — с подтверждения пользователя.
- Порог полного прогона тестов ≤ 60 с (Р8, Р27). Публикация (пуш, релизы) — только с подтверждения пользователя.
- Графика импорта в корне репозитория не лежит: сцены — с `D2_ASSETS_DIR` (например, `../disciples-godot/assets`), без ссылок и junction.
- Ветки → слияние в `main` (`--no-ff`); ревью подагентом и документы — раз на 3–4 правки, замер — на каждую (кадр, загрузка, память —
  `bench`, `ab.py` и `perf-log.md`). Пользователю — по-русски, коротко. Маршруты по интерфейсу спрашивать у пользователя — он знает игру.
- Условие §3.4: схема содержимого (C) и реестр эффектов (D) приняты до первой строки кода Студии — проверь, что это так, прежде чем начинать.

**Задачи по порядку (roadmap §4, Э6)**
0. **Перед началом:** после пулла — `dotnet run --project tools/RulesImport` (база содержимого с `look` рас); проверки и бенч зелёные.
1. **Дерево построек данными** (§3.3): постройки, ветки и связи — из содержимого (`BuildingDef`: `Level`, `Requires`, `Branch`), число веток
   — из данных; автораскладка по уровню и требованию, позиция мода главнее; слои модов.
2. **Новое окно построек** на `Control`: рамки (9-patch) и линии — кодом, область с `ClipContents` и `Node2D` с масштабом и сдвигом: зум
   колесом к курсору с пределами, тащение СКМ, ограничение по рамке содержимого; проверка попадания — в `LastEdict.Data` с обратным
   преобразованием (проверки без движка); геймпад (указатель, крестовина) и HD-кадры значков — как у прочих окон. Зум — в точках экрана
   (HD-значки через `ImageScales.Texture`, фильтр `ImageScales.Filter`), подписи — шрифтами `GameData.Fonts` (векторный текст): при
   увеличении ни значки, ни текст не должны мылиться.
3. **Студия: ядро `Authoring` + CLI `d2mod`** (§3.4, Р20, Р21): отмена командами ядра; «папка = сущность»; автоматические id строк;
   мод с C#-плагином помечается «исполняет код».
4. **Рабочее пространство «Дерево построек»**: двухпанельный UX (граф цепочек `Requires` с юнитом здания слева, живая страница окна справа),
   перетаскивание, проверка циклов, панель ошибок; игра — отдельный процесс `--mods --scenario --watch`, горячая перезагрузка
   (`FileSystemWatcher`, ревизия реестра).
5. **Содержимое и Баланс/Арена**: правка сущностей по схеме; цикл «изменил → прогнал → сравнил» на `BattleSim` и стенде баланса
   (`tools/BalanceStand`) без запуска игры.
6. **Редактор карт без потолка площади** (Р6, Р16): квадратные карты, все массивы по размеру карты; замеры 256², 512², 1024² (память тумана,
   A*, ход ИИ) — при росте стоимости разбить карту на зоны.
